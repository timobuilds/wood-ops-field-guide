# Schedule around the constraint

## Job to be done

**Situation.** Ready work queues, a department stays overloaded, or excess work in progress slows orders.

**Deliverable.** A capacity-tested release schedule and a rule for stopping upstream release.

Turn the request into a draft objective in the user’s terms: “When [circumstance], help [person] achieve [observable progress] so [customer or business outcome].” Add a baseline, desired result, owner and review point if known. Mark proposed targets as proposals. When no baseline exists, specify the smallest observation needed to establish one. Continue with the evidence available.

## Work through the decision

1. Follow ready orders and distinguish a persistently loaded operation from one starved for parts, instructions or staff. Check load by product family and available productive hours. Record what would disprove the suspected constraint.

2. Build a feasible daily bucket using the limiting operation and the promised mix. Express load in the unit that consumes capacity. Protect the sequence from upstream optimization. Allow an explicit buffer for variability and a limit at which upstream stops releasing.

3. Pilot on one stream. Track good completions at the constraint, queues, lead time and whole orders shipped. Tighten the bucket only once it reliably completes. Recheck where the constraint moved.

## Return to the user

Produce the deliverable above using the user's facts. Identify the decisive unknown and how to test it. Finish with the next action, proposed owner, review point and the observation that would justify a different decision. Clearly distinguish observed results, estimates and recommendations. Cite the specific column when explaining its teaching. The JTBD and deliverable are adaptations of Sepp Gmeiner’s writing.

**Example request.** We release a week's orders on Monday and everything is urgent by Thursday.

## Source lessons

- Limit upstream release when a defined buffer is full; support the downstream operation pulling work. [Pull!](https://www.woodworkingcanada.com/r5/showkiosk.asp?listing_id=5930846&switch_issue_id=60989)
- Schedule to the product mix the limiting operation can complete; machine counts alone hide overload. [Know your bottleneck and improve your scheduling](https://www.woodworkingcanada.com/r5/showkiosk.asp?listing_id=5900951&switch_issue_id=60989)
- Expose hidden constraints by reducing unnecessary buffers and start with an actionable improvement. [Where do we start?](https://www.woodworkingcanada.com/r5/showkiosk.asp?listing_id=5768403&switch_issue_id=60989)
- Release manageable time buckets that can finish, balanced by capacity and mix. [Production scheduling](https://www.woodworkingcanada.com/r5/showkiosk.asp?listing_id=5703147&switch_issue_id=60989)
- Use downstream consumption to pace upstream work; local utilization can inflate inventory. [Pull vs. push](https://www.woodworkingcanada.com/r5/showkiosk.asp?listing_id=5748691&switch_issue_id=60989)
